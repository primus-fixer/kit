# kit — общий модуль приложений

Общая часть приложений «Полка», «Карман», «Ящик» и «Мост» (Tauri 2, React и Rust, Windows и Android):
то, что в них было одинаковым и правилось в каждом отдельно. В приложении остаются его записи,
экраны и инструменты для Claude.

## Как подключить

В `Cargo.toml` приложения — зависимость от нужной версии по метке:

```toml
kit-core = { git = "https://github.com/primus-fixer/kit", tag = "v0.1.0" }
kit-secure = { git = "https://github.com/primus-fixer/kit", tag = "v0.1.0" }
kit-tauri = { git = "https://github.com/primus-fixer/kit", tag = "v0.1.0" }
```

Метку версии ставит владелец репозитория на GitHub (Releases → новый выпуск с меткой `vX.Y.Z`
на `main`). Пока метки нет, приложение ссылается на коммит: `rev = "<номер коммита>"` вместо `tag`.

Чем приложение отличается от других, оно описывает один раз — своим названием и строками ключей:

```rust
use kit_core::AppNames;
use kit_secure::KeyNames;

pub const APP: AppNames = AppNames { id: "polka", name: "Полка", name_acc: "Полку", name_gen: "Полки" };
pub const KEYS: KeyNames = KeyNames { dpapi_entropy: b"polka-db-key-v1", dpapi_label: "Polka", keystore_alias: "polka-db-key" };
```

**Строки ключей у выпущенного приложения менять нельзя:** с другими строками система не расшифрует
ключ базы, который уже лежит на устройстве.

Вход подключается в три шага (пример — `app/src-tauri/src/lib.rs` «Полки»):

1. при запуске создать `kit_tauri::guard::Lock` и отдать его Tauri: `app.manage(lock.clone())`;
2. вписать команды `kit_tauri::guard::*` в `tauri::generate_handler!`;
3. сообщать о фокусе окна: `kit_tauri::guard::on_focus(app, focused)`.

Перед работой с данными приложение спрашивает `lock.check()`: пока оно заблокировано, ответ — `locked`.

Коннектор для Claude (`kit_core::mcp`): приложение описывает себя — `Server` (имя, подсказка для Claude,
строка ключа связи), `Extension` (как расширение называется в приложении Claude) и список `Tool` — и
отдаёт строки запросов в `mcp::handle`. **Строку ключа связи у выпущенного приложения менять нельзя.**

Связь посредника с запущенным приложением (`kit_core::link`) описывает `Connector`: `Server`, `Extension`
(из него — переменная с папкой данных), название `AppNames` и идентификатор приложения (имя папки данных).
Запущенное приложение после открытия базы вызывает `link::listen(&CONNECTOR, папка, версия, |инструмент,
аргументы| …)`; `<программа> --mcp` — это `link::relay(&CONNECTOR, &инструменты, версия)`. Посредник прежней
версии и новое приложение понимают друг друга.

Резервная копия (`kit_core::backup`): приложение задаёт `Format` — метку в начале файла (**у выпущенного
приложения не менять**), расширение, название, свои слова-пароли и свои виды записей — и пишет копию
через `Writer` (сведения о копии `Manifest<свои счётчики>`, события, вложения, свои записи), а читает через
`Reader`. Что класть в копию и как добавлять прочитанное в базу, решает приложение. Ключ из пароля
(`derive_raw`, `Kdf`) — тот же, что у облака.

Синхронизация (`kit_core::sync`): база приложения реализует `Journal` — какие события есть, какие отдать,
как принять чужие, вложения и (если нужно) большие файлы кусками. Обмен по любому каналу `Wire` —
`run_client` и `run_server` с настройками `Profile` (версия, поле `files` для старых версий «Кармана»,
с какой версии другая сторона передаёт большие файлы). Сообщения — те же байты, что у приложений до kit.

Связь по Wi-Fi (`kit_core::lan`): приложение задаёт свои настройки `Lan` — порты, метки пакетов, имена сторон
SPAKE2 и личную строку для вывода ключей (у каждого приложения свои, чтобы они не мешали друг другу в одной
сети), — и пользуется `Server` и `Responder` (ждать связи и отвечать на поиск), `pair_join` (связаться по коду),
`sync_peer` (обмен по ключу пары) и `discover` (поиск). Что делать с найденными устройствами и ключами пар,
решает приложение (`Host`: где ключ пары, что запомнить при связи, что сделать после обмена). Код из восьми
знаков — `new_code`, `normalize_code`, `show_code`; адреса из QR-кода проверяет `is_local_address`.

Облако (`kit_core::cloud`): приложение задаёт `Format` — файл ключа, метку файлов, расширения, как называются
вложения в сообщениях и какие подходят, большие файлы кусками (если есть). База реализует `CloudStore` поверх
`Journal` (события по номерам, расхождение записей, какие вложения есть), само облако — `Cloud` (список, чтение,
запись, удаление файла в папке). Подключение по паролю копий — `join`, обмен — `sync` с `State` между обменами,
смена пароля — `put_key_file`, удаление данных — `wipe`. Для проверок без сети — `MemCloud`.

Клиент WebDAV (`kit_cloud::dav::Dav`): `Dav::new(&FORMAT, сервер, логин, пароль)` — облако `Cloud` в папке
приложения; Яндекс Диск — сервер `YANDEX`. Свои облака приложения (у «Кармана» — вход по коду в Яндекс
и Google Drive) пользуются теми же запросами (`kit_cloud::http`). Для проверок без сети — `kit_cloud::mock`
(признак `mock`): сервер WebDAV в памяти.

База (`kit_core::db`, признак `db`: `kit-core = { …, features = ["db"] }`): `db::open(путь, ключ)` открывает
базу SQLCipher и создаёт таблицы `meta`, `events`, `items`, `blobs` (**их поля не меняются**); остальное — функции
над соединением: местные значения (`meta`, `set_meta`, `meta_prefix`), журнал (`next`, `insert_event`, `versions`,
`events_after`, `events_range`, `events_by_lamport`, `event_body`) и вложения (`insert_blob`, `blob`, `has_blob`).
Тело события — строка JSON приложения; как событие становится записью, решает приложение.

Записи приложения (`kit_core::store`, признак `store`): `Store::open(путь, ключ, устройство, &BLOBS)` — база
с журналом «вид, номер, содержимое»: `put(вид, номер, &значение)`, `get`, `list`, `delete`. Каждое изменение —
событие с часами Лэмпорта; при споре устройств побеждает более позднее. Вложения — по SHA-256; какие подходят и в
каких полях записей на них ссылаются, приложение задаёт в `Blobs` (`NO_BLOBS` — без вложений). `Store` сам реализует
`Journal`, `CloudStore` и `lan::Device`, поэтому обмен по Wi-Fi и облако работают без кода приложения. Тело события —
то же, что у «Полки»: её база открывается хранилищем как есть (проверка — на образце «Полки» 0.11.1). Свои таблицы
без обмена — через `Store::conn`.

Обмен в приложении (`kit-tauri`): приложение отдаёт Tauri состояние и вписывает команды одной строкой —
команды Tauri не бывают обобщёнными, поэтому их создаёт макрос в самом приложении:

```rust
kit_tauri::wifi_commands!(Store);   // lan_status, lan_scan, lan_code_start, … lan_unpair
kit_tauri::cloud_commands!(Store);  // cloud_status, cloud_dav_login, cloud_password, … cloud_disconnect
```

`wifi::Wifi::new(&LAN, &KEYS, база, номер устройства, имя)` и `cloud::Sky::new(Settings, база, свой вход)`
кладутся в `app.manage`, `wifi::start` и `cloud::start` запускают фоновый обмен. База реализует `Device`
(свои значения в `meta`) и `CloudStore`. Свой способ входа в облако приложение передаёт в `Sky` как `Extra`
(у «Кармана» — вход по коду), его команды остаются в приложении. Ключи в `meta` (`cloud.*`, `lan.peers`)
те же, что у приложений до kit.

## Заготовка нового приложения

Новое приложение начинается с заготовки: сразу со входом по PIN-коду, отпечатку и Windows Hello, базой с журналом
записей, обменом по Wi-Fi и облаком, экранами (главный и настройки) и сборками для Windows и Android.

```
python3 scripts/new-app.py --id yashik --latin Yashik --name Ящик --acc Ящик --gen Ящика \
    --tag YSH --tcp 47520 --udp 47521 --desc "Ящик — почта: все ящики в одном месте" \
    --kit-rev <коммит или метка kit> ../yashik
```

- `--id` и `--latin` — название латиницей: из него строки ключей, имена файлов, папка данных и идентификатор
  приложения; `--name`, `--acc`, `--gen` — название в трёх падежах, `--feminine` — женского рода.
- `--tag` — три буквы для меток пакетов связи и файлов облака, `--tcp`/`--udp` — порты связи по Wi-Fi. Занятые
  «Карманом» и «Полкой» скрипт не даёт.
- **Эти строки у выпущенного приложения не меняются** — их закрепляют проверки в самом приложении.

Что внутри — `template/` (те же файлы, что получит приложение, с подстановками `__ID__`, `__NAME__` и др.).
Своё приложение дописывает: записи — в ядре `crates/<id>-core`, команды — в `app/src-tauri/src/lib.rs`, экраны —
в `app/src`. Проверка заготовки — `bash scripts/test-new-app.sh`: из неё создаётся приложение с kit из этой
папки и проходит свои проверки.

## Интерфейс

Пакет npm `@primus-fixer/kit` — прямо из этого репозитория, без сборки: исходники TypeScript собирает
Vite приложения. В `app/package.json`:

```json
"@primus-fixer/kit": "git+https://github.com/primus-fixer/kit.git#<версия kit>"
```

В `main.tsx` — шрифты и общие стили, затем свои стили приложения:

```ts
import '@primus-fixer/kit/ui/fonts';
import '@primus-fixer/kit/ui/styles.css';
import './styles.css';
```

Приложение, которое ещё не перешло на стили kit целиком, может взять только экран входа: вместо
`styles.css` — `@primus-fixer/kit/ui/lock.css` (он самостоятельный: нужны только переменные цветов
из `applyTheme`). Оба приложения с 0.11.0 берут `styles.css` целиком.

Что есть в `@primus-fixer/kit/ui`:

- `SCHEMES`, `applyTheme` — пять цветовых схем, светлая и тёмная тема;
- `Icon`, `addIcons` — значки; свои приложение добавляет к значкам kit;
- `Seg`, `Cut`, `Row`, `Header`, `Bar` — переключатель, раздел под катом, строка, верхняя строка, полоса;
- `TitleBar`, `customTitleBar`, `setTitleBarColors` — своя полоса окна на компьютере;
- `LockScreen`, `PinFlow`, `bioLabel`, `lockCommands` — экран входа и экраны PIN-кода. Название
  приложения (`names`) и команды входа (`api`) передаёт приложение: в самом приложении это
  `lockCommands()` — команды `kit-tauri`, в демо в браузере — свои;
- `WifiSection`, `CloudSection` — разделы настроек «Обмен по Wi-Fi» и «Облако». Слова приложения
  (`WifiWords`, `CloudWords`: название, род, что за вложения) и команды (`wifiCommands()`, `cloudCommands()`;
  `cloudCommands(true)` — ещё и вход по коду) передаёт приложение; `wrap` — свой заголовок раздела;
- `stored`, `store` — настройки вида на этом устройстве.

Как ими пользоваться и какие у элементов классы — [docs/design.md](docs/design.md).

## Сборки

Сценарий сборок приложения вызывает общие сценарии kit. Приложение лежит в папке `app/` (Tauri 2, npm);
имя программы, название и версия берутся из `app/src-tauri/tauri.conf.json`.

```yaml
jobs:
  windows:
    uses: primus-fixer/kit/.github/workflows/windows.yml@<версия kit>
    with:
      mcp-tool: add_title            # проверить, что «polka.exe --mcp» знает этот инструмент; можно не задавать
  android:
    uses: primus-fixer/kit/.github/workflows/android.yml@<версия kit>
    with:
      title: Полка                   # название под иконкой
      key-alias: polka               # псевдоним ключа подписи, если нет секрета ANDROID_KEY_ALIAS
      kit-ref: <та же версия kit>
    secrets:
      ANDROID_KEYSTORE: ${{ secrets.ANDROID_KEYSTORE }}
      ANDROID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
      ANDROID_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
```

- **Windows:** установщик `.exe` и `.msi` в артефакте `<программа>-windows`. Перед сборкой можно
  проверить пакеты Rust на Windows (`tests: -p …`), после — ответ коннектора для Claude (`mcp-tool`).
- **Android:** `<Название>-<версия>.apk` в артефакте `<программа>-android`. С секретами
  `ANDROID_KEYSTORE` и `ANDROID_KEYSTORE_PASSWORD` APK подписан постоянным ключом и ставится поверх
  прежнего, без них — отладочная сборка.
- **Донастройка Android:** сначала общий `scripts/android-patch.sh` kit — название под иконкой, иконки,
  разрешения сети, запрет копии Android, targetSdk; затем свой `scripts/android-patch.sh` приложения,
  если он есть, — главное окно, «Поделиться», виджеты.

Когда запускать сборки, решает приложение (`on:` в своём сценарии). Общий скрипт проверяется
на образце проекта `tauri android init` (`scripts/test-android-patch.sh`).

## Правила

- **Форматы не меняются.** Базы, резервные копии, файлы в облаке и связь устройств, сделанные
  прежними версиями приложений, должны работать. Это закреплено проверками на образцах — файлах,
  которые сделали выпущенные версии.
- **Версии** — метки `vX.Y.Z`. Приложение само решает, когда перейти на новую.
- **Приложения различаются настройками**, а не правками в модуле: название, строки ключей, порты,
  имена файлов.

## Проверки

```
cargo test --all-features
bash scripts/test-android-patch.sh
bash scripts/test-new-app.sh # заготовка нового приложения собирается и проходит свои проверки
npm ci && npm run check      # типы интерфейса
```

На Windows дополнительно проверяется, что ключ, сохранённый «Полкой» и «Карманом» до модуля,
открывается модулем.
